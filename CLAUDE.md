# Jingle Code: зимний пиксельный плагин для IDE JetBrains

Репо `jingle-code`. Это новый самостоятельный проект, пишется с нуля.

Плагин создаёт зимнее праздничное настроение прямо в окне IDE. Польза вторична. Автор и пользователь — Иван, бэкендер (Kotlin/Java). Общаемся по-русски, код и идентификаторы на английском, тексты интерфейса через resource bundle.

Полное описание в `docs/SPEC.md`, порядок работ в `docs/ROADMAP.md`, принятые решения с причинами в `docs/DECISIONS.md`. Живой макет: `docs/mockup/jingle-code-mockup.html` (открыть в браузере), он же опубликован по адресу https://claude.ai/artifact/NdmDccMxAvFaF5TS8DnCGG.

## Правила, которые нельзя нарушать
- **Не мешать работе.** IDE — рабочее место. Ничего не рисуем поверх кода, кроме снега и деревни внизу редактора (решение Ивана: деревня поверх кода, а не под ним). Снег по решению Ивана он включён по умолчанию и всегда под рукой — кнопка в правом верхнем углу редактора (снежинка — снег, домик — звёзды над деревней) и переключатель в настройках. Никаких попапов ради декора; кликать по декору не обязательно, но можно (дым по клику на дом).
- **Нативно.** Декор прилегает к настоящим краям интерфейса: щелям между панелями, нижнему краю редактора, низу панели Project, тулбару, строке состояния. Никаких «прямоугольников в воздухе».
- **Без полупрозрачности.** Блёклый декор выглядит как призрак. Цвета насыщенные, как в макете.
- **Пиксель-арт.** Рисуем в логических пикселях с целочисленным масштабом (`JBUIScale`), интерполяция `VALUE_INTERPOLATION_NEAREST_NEIGHBOR`, без сглаживания. Анимация спрайтов 6 кадров по 120–150 мс через `javax.swing.Timer`. Непрерывное движение (падающий снег) идёт по плавному такту `JingleAnimator.subscribeMotion`, около 30 раз в секунду, как в макете, но по той же пиксельной сетке.
- **Экономно.** Анимация стоит на паузе, когда окно IDE не в фокусе, в Power Save и в Presentation mode. Всё выключается в настройках, звук по умолчанию выключен.
- **Сезон.** Плагин сам включается в начале декабря и сам убирает украшения в конце сезона (по умолчанию после Старого Нового года, 14 января).
- **Чужие персонажи под запретом.** Никакого Гринча и имени «Рудольф»: это защищённые персонажи. Олень с красным носом без имени — можно.

## Технически
- Шаблон: IntelliJ Platform Plugin Template, Gradle (Kotlin DSL), IntelliJ Platform Gradle Plugin 2.x.
- Группа `io.github.ioannvs`, id `io.github.ioannvs.jinglecode`, `<name>Jingle Code</name>`. Пакеты `io.github.ioannvs.jinglecode.<фича>`.
- Основа зависит только от `com.intellij.modules.platform`, чтобы работать во всех IDE JetBrains. Git (`Git4Idea`) и всё, что специфично для IDE (события сборки Java/Gradle), подключаем как `optional="true"` зависимости с отдельными `config-file`.
- `sinceBuild = 251`, `untilBuild` не указываем.
- Публичный API в приоритете. Всё, что требует внутреннего API (`@ApiStatus.Internal`, раскладка Swing-компонентов), прячем за отдельной настройкой и изолируем в одном месте, чтобы при поломке отключить только это.
- Настройки: `JingleCodeSettings` (`SimplePersistentStateComponent`, `jingle-code.xml`) и `JingleCodeSettingsListener` на message bus. Страница настроек: Settings → Appearance → Jingle Code. Тексты в `messages/JingleCodeBundle.properties` и `JingleCodeBundle_ru.properties`.
- Время берём только из `core/JingleClock`, никаких `LocalDate.now()`. События — через `events/JingleEvents`, код про Git только в пакете `git` (проверяет `ArchitectureTest`). Показывать ли фичу, решает `core/FeatureGate` (плагин включён, сезон, переключатель, не сломана); декор слушает `FeatureGate.TOPIC`, а хрупкий код оборачивает в `FeatureGate.guard`. Новый элемент декора — новое значение `JingleFeature`. Архитектура и порядок её ввода — в `docs/DECISIONS.md`.
- `verifyPlugin` запускаем перед каждым релизом и по расписанию в CI против последнего релиза и EAP.

## Как работать
- Собрать и запустить: `./gradlew runIde` (на Windows `gradlew.bat runIde`). Другой день в песочнице: `./gradlew runIde -PjingleNow=2026-12-31T23:59` (или только дата). Проверка совместимости: `./gradlew verifyPlugin`, она долгая, в обычной работе не запускаем.
- Спрайты переносим из макета один в один: каждая функция `drawXxx` в `docs/mockup/jingle-code-mockup.html` рисует по пикселям через `px`/`rect`, это легко перевести в Kotlin-объект с `fillRect`. Палитры (`FIRE`, `BULBS` и т.д.) выносим в один `JinglePalette`.
- Каждую фичу показываем Ивану в `runIde` до того, как идти дальше. Он решает сам. Предлагаем варианты с рекомендацией.
