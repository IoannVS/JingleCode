# Jingle Code: решения и почему

Журнал решений из обсуждения с Иваном 29–30 октября 2026. Новые решения дописываем вниз.

- **Цель — настроение**, польза вторична. Сезон с декабря до середины января.
- **Гирлянда по верхнему краю окна отвергнута**: она закрывает текст и иконки тулбара. Ни один элемент не должен перекрывать UI.
- **Гирлянда живёт в щелях между панелями**, а не поверх интерфейса.
- **Камин по клику в строке состояния отвергнут**: «сомнительный UX». Атмосфера должна быть встроена и видна всегда, без кликов.
- **Камин в пустом редакторе принят.**
- **Полупрозрачная деревня отвергнута**: «выглядит как призрак, а это не Хэллоуин». Только насыщенные цвета.
- **Деревня и сугроб в панели Project не могут быть прямоугольниками**: «не нативно». Декор прилегает к краям UI и повторяет скругления.
- **Снег только в щелях был слишком скупым.** Добавлены три режима снега в редакторе, все три идут в настройки, выбирает пользователь.
- **Гринч и имя «Рудольф» не используем**: защищённые персонажи, риск жалобы в Marketplace. Замена: сорока-воровка, олень без имени.
- **Все события, пасхалки и элементы в настройках**, каждый пользователь решает сам.
- **Название: Jingle Code**, репо `jingle-code`, id `io.github.ioannvs.jinglecode`. Рождественское имя подходит, потому что сезон заканчивается на Старом Новом годе.
- **Имя плагина одно на все языки.** Локализуем только тексты внутри, есть свой переключатель «Язык и праздники».
- **Совместимость**: основа на платформе для всех IDE, Git и сборка как optional-модули.

## Шаг 0, каркас (30 октября 2026)
- **Проект из мастера New Project IDEA**, а не из GitHub-шаблона: Gradle 9.7.1, IntelliJ Platform Gradle Plugin 2.19.0. Демо-окно шаблона удалено.
- **Компилируем против IDEA 2025.3**, `sinceBuild = 251`, `apiVersion = 2.1` у Kotlin (2025.1 несёт Kotlin 2.1), stdlib не пакуем. Что API из 2025.1 не потерялось, проверяет `verifyPlugin`: последняя 2025.1.x, последний релиз и последний EAP.
- **`instrumentCode = false`**: инструментация нужна только для `.form` и `@NotNull` в Java, а с Microsoft JDK она падает.
- **`PixelCanvas` рисует в пикселях устройства**: размер логического пикселя = user scale × HiDPI scale, округлённый до целого. Так пиксели одинаковые на 125 % и 150 %. Округление координат как у `Math.round` в JS, `hash` перенесён как есть, чтобы спрайты совпадали с макетом.
- **`JingleAnimator`**: сервис проекта, один `javax.swing.Timer` на 140 мс, 6 кадров. Работает, только пока есть подписчики, анимация включена и активно окно проекта или его диалог (например, Settings). Пауза в Power Save и Presentation mode. На паузе декор показывает последний кадр.
- **Палитра без `JBColor` и альфы**: декор одинаковый в светлой и тёмной теме, цвета из макета. Цвета спрайта добавляем в `JinglePalette` при переносе.
- **Предпросмотр на странице настроек** (огонь, гирлянда, палитра): нужен, чтобы шаг 0 было видно в `runIde`.

## Шаг 1.0, гирлянда в щелях (30 октября 2026)
- **Щели в Islands узкие**: соседние острова стоят вплотную, видимая щель — их собственная скруглённая рамка, 4–7 физических пикселей при 125 %. Макет рисовал щель 10 CSS-пикселей при 2 px на логический пиксель, в IDE так не выйдет.
- **Размер гирлянды — как в макете по отношению к интерфейсу** (решение Ивана: при 1 px на логический пиксель вышел «бисер»). В макете логический пиксель 2 px при шрифте 12 px, значит пиксель гирлянды = шрифт интерфейса / 6: при 125 % это 3 физических пикселя, лампочка 6×6. Размер следует за шрифтом IDE.
- **Форма как в макете**: провод вьётся волной, лампочки висят попеременно с двух сторон. Гирлянда шире щели и лежит на пустых скруглённых краях островов, до содержимого (дерево, код) не достаёт. Строгое «только внутри щели» отменено: в щель 4 px гирлянда нужного размера не помещается.
- **Нитка над строкой состояния без провиса и подвешена к нижней кромке островов** (решение Ивана): провод на кромке, лампочки в свободной полосе и заканчиваются ровно над иконками строки состояния. Для провиса места нет.
- **Рисуем сверху, через painter стеклянной панели (`IdeGlassPane.addPainter`)**, с клипом по полосе вдоль щели и за вычетом попапов, балунов и выезжающих (sliding) tool windows. Нарисовать «под» островами нельзя: щель — это рамка самого острова.
- **Свой `Painter`, а не `AbstractPainter`**: тот рисует только после `setNeedsRepaint`, и гирлянда пропадала бы при любой чужой перерисовке.
- **Геометрия только из публичного API** (`ToolWindow.component`, `FileEditorManagerEx.component`, `StatusBar.component`), но опирается на раскладку Swing: остров — самый верхний предок, в котором нет других островов. Всё это в `GapFinder`; при исключении гирлянда выключается до перезапуска.
- **Только в Islands** (ключ темы `Islands`). Классический UI — потом, отдельным запасным вариантом.
- **Режимы**: мерцание (как в макете), бегущий огонь (горят пары лампочек, бегут), перелив (горят все, цвета текут), тёплый белый (с редкими искрами). Блик лампочки `#ffffffaa` из макета заменён заранее смешанным непрозрачным цветом.

## Архитектура под весь роадмап (30 октября 2026)
Вводим по мере надобности, а не заранее: каждая часть появляется вместе со второй фичей, которой она нужна.
- **`core/JingleClock` — единственный источник «сейчас».** `LocalDate.now()` напрямую не вызываем. В песочнице дату подменяет `./gradlew runIde -PjingleNow=2026-12-31T23:59` (или только дата), подменённое время идёт дальше. Без этого декабрьское не проверить в октябре.
- **`core/Season`**: сезон 1 декабря – 14 января включительно, режимы авто / всегда / выкл в настройках.
- **`core/FeatureGate` решает, показывать ли фичу сейчас**: плагин включён, идёт сезон, фича включена, фича не сломалась. Публикует `FeatureGate.TOPIC`, когда ответ мог измениться: после изменения настроек, в полночь (сезон начинается и кончается сам) и при поломке фичи. Декор слушает этот топик, а не настройки.
- **`FeatureGate.guard(feature)`** вместо своего флага `broken` в каждой фиче: при исключении пишет в лог один раз и выключает фичу до перезапуска. Через него идёт всё, что опирается на раскладку Swing или внутренний API.
- **`JingleFeature`** — по значению на каждый элемент со своим переключателем. Подписка на `JingleAnimator` указывает фичу, таймер идёт, только пока хоть одна из них активна (предпросмотр в настройках подписан без фичи). Вне сезона таймер стоит.
- **Дальше по шагам**: на 1.4 (сосульки) общий слой поверх окна `overlay/FrameOverlay` + `OverlayLayer`, `GapFinder` → `FrameGeometry`; на шаге 2 свой бандл с локалью из настройки «Язык и праздники» (`DynamicBundle` следует языку IDE); на шаге 3 `events/`: `JingleEvent` на шине проекта, `EventThrottle`, `JingleProjectState`, источники Git и сборки в optional-модулях публикуют события, декор о Git не знает; на шаге 6 `experimental/` за `guard`.
- **Направление зависимостей**: декор → `core`/`animation`/`pixel`/события; `core` и декор не импортируют `git/` и `build/`.

## Шаг 4, снег в редакторе: только «поверх кода» (30 октября 2026)
- **Решение Ивана: из трёх режимов делаем один — снег поверх всего редактора, без паузы при печати.** Режим «в пустом месте» (сугробы на строках) сделан и откачен.
- **По умолчанию выключен**: снег идёт поверх кода, а поверх кода рисуем только то, что пользователь включил сам. Настройка «Снег в редакторе: нет / поверх кода».
- **Рисуем через `CustomHighlighterRenderer`** на `RangeHighlighter` поверх всего документа в `markupModel` самого редактора, после текста. Снег внутри редактора, поэтому попапы и автодополнение сами оказываются над ним. Порядок задаём через `getOrder() = AFTER_TEXT`: API помечено `@Experimental`, но старый `isForeground()` deprecated и идёт под удаление.
- **Только редакторы кода** (`EditorKind.MAIN_EDITOR`) своего проекта: не консоли, не diff, не предпросмотр.
- **Логический пиксель снега — десятая часть строки редактора**, как в макете (строка 20 px, пиксель 2 px): снег следует за шрифтом и зумом редактора. Плотность и скорость как в макете: снежинка на 400 логических пикселей, 7–16 пикселей в секунду.
- **Снег привязан к окну редактора**, не к тексту: при прокрутке он идёт на месте.
- **На светлой теме снег цвета льда** (`ICE`), на тёмной белый (`SNOW`): белый на белом не виден.
- **Каждый кадр перерисовывается видимая часть редактора**: снег разбросан по всему окну, `RepaintManager` всё равно слил бы полосы в одну область.
- **Снег падает плавно** (просьба Ивана: раз в 140 мс снежинка прыгала на 1–2 пикселя). В макете снег движется на каждом кадре браузера, а не по 6-кадровому циклу. У `JingleAnimator` второй такт `subscribeMotion`, примерно 33 мс, с реальным `dt` (не больше 50 мс, как в макете) и теми же паузами: окно не в фокусе, Power Save, Presentation mode, фича неактивна. Пиксельная сетка та же, плавность от частоты. Редактор перерисовывается только на тех кадрах, где хоть одна снежинка перешла в соседний пиксель.
- **Снег включён по умолчанию** (решение Ивана), вместо «включает сам пользователь». Выключается в один клик: **кнопка-снежинка в правом верхнем углу редактора**, в ряду виджета инспекций, слева от счётчиков ошибок (просьба Ивана; сначала была под виджетом, в плавающем тулбаре `editorFloatingToolbarProvider`). Публичный EP `iw.actionProvider` (`InspectionWidgetActionProvider`), там же кнопка Reader Mode. Только в редакторах кода; вне сезона и при выключенном плагине кнопки нет. Кнопка — обычное действие, не `ToggleAction` (просьба Ивана: без фона нажатой кнопки, просто снежинка): снег идёт — снежинка яркая, нет — серая (`IconLoader.getDisabledIcon`). Переключает тот же флажок, что и в настройках. Иконка — пиксельная шестиконечная снежинка 16×16 с перекладинами на лучах (`icons/snowflake.svg` и `_dark`).
- **Режим снега сведён к флажку** «снег падает в редакторе»: из режимов остался один.
- **Количество снега — словами**: редкий / обычный / густой, одна снежинка на 800 / 400 / 200 логических пикселей (обычный как в макете).
- **Скорость падения** («частота» в просьбе Ивана): медленно / обычно / быстро, ×0,5 / ×1 / ×2 к скорости из макета (7–16 пикселей в секунду), покачивание не меняется.
- **Плавность** (сначала «частоту» понял так, Иван оставил и её): экономно 15 / 20 / плавно 30 кадров в секунду, по умолчанию 30. Интервал плавного такта `JingleAnimator.subscribeMotion` задаёт подписчик и перечитывается при изменении настроек.

## Шаг 1.4, сосульки под тулбаром (30 октября 2026)
- **Общий слой поверх окна, как и планировали к этому шагу.** `overlay/FrameOverlay` — один painter на glass pane для всего декора у краёв панелей. Он держит кэш геометрии, перерисовывает только полосы слоёв и вырезает попапы и выезжающие tool windows. `OverlayLayer` — один слой: говорит, где рисует, и рисует там. Сейчас слоёв два: `GarlandLayer` и `IciclesLayer`. `GapFinder` стал `overlay/FrameGeometry` и ещё находит верхний край панелей, `GarlandManager` и `GarlandStartupActivity` заменены на `FrameOverlay` и `FrameOverlayStartupActivity`.
- **Если геометрия падает, выключаются все слои оверлея**: у `FeatureGate.guard` есть вариант для нескольких фич. Если падает отрисовка одного слоя, выключается только он.
- **Сосульки висят от нижнего края тулбара**, как в макете. В Islands верхний ряд островов начинается сразу под тулбаром, а полоска под ним — их собственная скруглённая рамка. Поэтому линия сосулек — верхний край верхнего ряда островов (`FrameGeometry.topEdges`), по одной на каждую группу соприкасающихся островов. Сосульки уходят вниз, в эту рамку.
- **Рисунок один в один с макетом**: сосулька в каждом втором столбце, примерно треть пропущена (`hash(x, 7) < 0.35`), длина 1–4 пикселя (`hash(x, 8)`), сверху снег, дальше лёд, кончик голубой. Раз в 3 кадра кончик может блеснуть белым (`hash(x, t / 3) > 0.97`).
- **Над вертикальными щелями сосулек нет**: там висит гирлянда. В макете пропуск один столбец, у нас на всю ширину гирлянды (±3 пикселя).
- **Размер пикселя у всего оверлея один**, от настройки размера гирлянды и шрифта интерфейса (`OverlayScale`): сосульки того же масштаба, что и гирлянда.
- **Отдельный переключатель** «Сосульки под тулбаром», по умолчанию включён.
- **Риск**: длинная сосулька (4 пикселя, около 9 px при 125 %) может доставать до заголовков верхних панелей и вкладок редактора, если рамка островов тоньше. Проверить в `runIde`; если достаёт, ограничить длину по высоте рамки.

## Шаг 1.5, сугроб в панели Project со снеговиком (30 октября 2026)
- **Третий слой оверлея**, `drift/DriftLayer`. Сцена перенесена из макета (`drawTreeSnow`) без событийных частей: подарки, письма, заяц, какао и таяние придут с событиями. Есть несколько падающих снежинок, сугроб волной от края до края с белой кромкой, почтовый ящик (пока пустой) и снеговик со шляпой, шарфом и морковкой. Каждый третий кадр он шевелит рукой.
- **Сцена стоит внизу панели всегда** (решение Ивана), даже когда дерево длинное: тогда она закрывает его нижние строки. Сначала была только в пустом месте под деревом, а когда места не хватало, пропадала целиком; Иван попросил рисовать всегда. Дерево из `ProjectView.currentProjectViewPane.tree` нужно только чтобы найти его область прокрутки. Высота сцены — 28 логических пикселей, как холст `tsnow` в макете.
- **Прилегает к краям панели и повторяет скругления** (решение «не прямоугольники»). Тело острова — его границы без рамки `Island.borderWidth`, углы — `Island.arc` из темы Islands. Сцена обрезается этим скруглённым прямоугольником, сугроб поднимается у боковых стенок, как в макете, и заполняет нижние углы. Сугроб рисуется на строку ниже и на столбец шире, чем помещается, чтобы при дробном размере панели не осталось щели у края.
- **Размер пикселя — общий для оверлея**, от настройки размера гирлянды. Отдельный переключатель «Сугроб со снеговиком», по умолчанию включён.

## Подарки за коммиты, первое событие (30 октября 2026)
- **Шина событий `events/`**, как в плане архитектуры: `JingleEvent` (`CommitsToday(n)`, `Commit`) на шине проекта, `JingleEvents.TOPIC`. Источники публикуют, декор слушает и не знает об источниках.
- **Подарков столько, сколько моих коммитов за сегодня** (решение Ивана). «Мои» — по `user.email` (или `user.name`) из git config каждого репозитория, через `GitUserRegistry`. Подсчёт: `git log --branches --since=<полночь> --author=<я> --fixed-strings`. Локальные ветки: удалённые посчитали бы запушенные коммиты дважды, а stash — не коммит дня. Считаем при открытии проекта, после любого изменения репозитория (`GitRepositoryChangeListener`: коммит из IDE или терминала двигает HEAD) и в полночь. Если коммитов стало больше, публикуется `Commit`, и новый подарок падает сверху, как в макете (22 пикселя за полсекунды). Мест под подарки 9, как в макете.
- **Даты коммитов реальные** (`JingleClock.realToday()`), даже когда песочница притворяется 20 декабря: иначе в ней всегда было бы 0 подарков. Это единственное исключение из «время только из `JingleClock`», и оно тоже идёт через `JingleClock`.
- **Без Git — 3 подарка** (решение Ивана: фиксированное число): если Git-плагина в IDE нет (`PluginManagerCore`, без классов Git) или в проекте нет Git-сопоставлений (`JingleEvent.NoRepositories`). **До первого подсчёта подарков нет**: раньше там было 3, и на старте они мелькали и пропадали, когда Git насчитывал 0 (Иван заметил это после полуночи). Если репозитории сопоставлены, но ещё не загрузились, ждём их.
- **Git — optional-зависимость** с `jingle-code-git.xml`. Весь код про Git в пакете `git`. `ArchitectureTest` проверяет, что больше никто не импортирует `git4idea` и этот пакет: иначе IDE без Git упала бы с `NoClassDefFoundError`. Состояние подарков (`drift/GiftPile`) слушает события через `projectListeners` в plugin.xml, чтобы не пропустить первый подсчёт.
- **Слои оверлея получают проект** в `OverlayLayer.paint`: сцене нужен её `GiftPile`.
- **Сборка**: после смены сигнатуры функции с параметрами по умолчанию Gradle build cache отдал устаревшие тестовые классы (`NoSuchMethodError`). Лечится `./gradlew test --no-build-cache --rerun-tasks`.
- **Сугроб — из округлых куч, а не волной** (Иван: «плосковатый, в макете пообъемнее»). Волна макета у нас — ровная одноцветная полоса с белой кромкой, и в широкой панели IDE она выглядит плоской. Теперь сугроб собран из куч: одна каждые 14–24 пикселя, 10–16 в каждую сторону, высотой 6–11 над слоем снега в 4 пикселя (Иван: «попышнее»), плюс куча до 15 пикселей у каждой стенки для скруглённых углов. Раскладка детерминирована (`hash` из макета). Свет сверху слева: макушки белые, правые склоны и складки между кучами цвета льда (`ICE`).
- **Внятная сцена** (Иван: «снеговик и подарки утопают», потом «ровное и снег — это неестественно»). Ровную площадку отвергли. Под предметами кучи сжаты до 40 % высоты, но остаются кочками, и к краям плавно растут до полной высоты. Каждый подарок на снегу, снеговик и столбик ящика стоят на самом высоком снегу под собой и утоплены на пиксель: щель под ними заполнена утоптанным снегом в тени, а кромка сугроба прикрывает их нижний ряд спереди. Верхние подарки едут вместе с теми, на которых лежат. Снеговик и подарки освещены так же, как сугроб: правые бока комов снеговика ледяные, и на снег под ним и под подарками падает ледяная тень. Иначе белый снеговик сливается с белым снегом. Сцену проверяли рендером в PNG настоящим кодом (временный тест через `PixelCanvas` в `BufferedImage`), без окна IDE.

## Подарки за незапушенные коммиты, сани с эльфами на push (31 октября 2026)
- **В кучке — мои незапушенные коммиты** (решение Ивана), а не коммиты за сегодня: `git log --branches --not --remotes --author=<я> --fixed-strings`. Число переживает перезапуск IDE и полночь; ветка без upstream считается незапушенной. Полуночного сброса и `JingleClock.realToday()` больше нет.
- **Мешок Санты пробовали и отвергли**: пиксельно выглядит не очень (Иван). Осталась кучка подарков из макета, до девяти, каждый стоит в снегу. Коммит — новый подарок падает сверху на своё место.
- **Нет коммитов — на снегу вмятины от подарков**: там, где стояли нижние подарки, снег продавлен на два ряда, края в тёмном льду (`ICE_TIP`), дно светлее.
- **Push — прилетают сани, эльфы грузят подарки, сани улетают** (решение Ивана). Сани из макета (`drawSleigh`, `drawReindeer`; олень с красным носом без имени) влетают слева и зависают над кучкой. Справа прибегают два эльфа: свои персонажи, красный колпак, острые уши, зелёный кафтан. Они по очереди подкидывают подарки в сани, сверху вниз, и запрыгивают следом. Сани улетают вправо, подарки видны в кузове, эльфы — головами. Остаются вмятины. Push видим по состоянию репозитория: незапушенных меньше и удалённые ветки сдвинулись. Так ловится и push из терминала; reset упряжку не зовёт.
- **Отклонённый push — сани возвращаются, эльфы выгружают** (как и решили для мешка: «привозит обратно»). Отказ — из `GitPushListener` (`REJECTED_*`, `ERROR`), только для push из IDE. Один визит за раз.
- **Расписание визита — чистая функция времени** (`drift/Delivery`): где сани, сколько подарков в кучке и в санях, какие летят, где эльфы. Её проверяют тесты без IDE. Визит длится 2–4 с на 1–9 подарков, возврат примерно вдвое дольше.
- **Сцене во время визита нужно небо**: слой сугроба забирает 18 логических пикселей над сценой (над нижними строками дерева, внутри панели), и оверлей на это время переходит на плавный такт (`OverlayLayer.isAnimating`, `subscribeMotion`).
- **Сборка**: после смены сигнатур инкрементальная компиляция и build cache отдают устаревшие тестовые классы (`NoSuchMethodError`). Лечится `./gradlew clean test --no-build-cache`.
